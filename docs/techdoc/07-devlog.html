CHAPTER 7

開発記録・知見 (2026 シーズン)

2026 年 8〜9 月に踏んだ問題を「症状 → 原因 → 対策 → 結果」の形で時系列に並べます。高速ターン (v = 1800〜2300) の duty 飽和と終端角度不足を軸に、FF ゲイン (Lm / Mass / Ke) の同定と座標系・積分器のバグ潰しを繰り返した 2 か月でした。制御の異常に見えた現象の多くは、左前タイヤの浮き、右エンコーダの磁石外れ、PSRAM の CE# 不良、モータードライバの coast 不感帯といった機体側の真因に行き着いています。並行して、ログから同定・判定する解析ツール群 (5 章) が整いました。

ハード制御ソフトツール同定

8 月

2026-08-20〜21

高速ターンのヨー I 項リセット

制御完了
症状
v = 1800〜2300 のターンで車頭角振動 (v = 2300 で平均 11.7°) と duty 99.9 % の飽和。旋回終了後もヨーレート I 項が残り振動が続く。
原因
旋回終了時の I 項再着火が img_ang − kim.theta (基準の違う 2 量) を拾い、数十度相当の汚染値を注入していた。
対策
SLALOM / SLA_BACK_STR から他へ遷移する時に w.error_i = 0。ヒステリシス脱出時のみ ang.error_p / dt で再着火。旋回終了にも /dt を使う案は悪化してリバート。
結果
v = 2200、n = 4 で角振動 −31 %、収束時間 −32 %、脱出後の I 項ピーク −61 %。v = 2300 は飽和のままで上限。
教訓
同じ「0 クリア → 残差で再着火」でも、トリガーが小残差を保証するかで安全性が変わる。無条件に発火するトリガーに /dt 系の再着火を使わない。
2026-08-22

減速指令の消失とエンコーダ KF の発散

ソフト完了
症状
v_max = 7000 で計画速度が 5544 に張り付き、終端まで減速せず急停止。FF のみ走行 (v = 400) で v_c2 が実測から乖離し負値まで発散。
原因
decel_delay_cnt/n が未配線で 0 → pow(0, 0) = 1 で減速量が 0 になる (v > 5500 のみ)。KF は「目標 v − 前 tick の実測 v」/dt という偽の加速度 (≈ −250,000) を毎 tick 注入していた。
対策
input_param_t に decel_delay_cnt (5) / n (4) を配線し yaml のタイプミスを修正。KF の予測入力を目標加速度 ego_in.accl に統一。
結果
v_max = 7000 で 5684 / 5756 mm/s のピーク後に滑らかに減速。FF のみ v = 400 で v_c = 658 に対し v_c2 = 665 と追従。
2026-08-22

Resist の同定と Ke / Km の差し戻し

同定完了
症状
ドライバ交換後に Resist = 4.4 Ω が未再校正ではと疑い、t2200 ターンの duty 飽和 (30〜35 %) の原因候補に挙がった。
原因
NFP-D0812 のデータシートの端子間抵抗は 4.4 Ω で一致。生成コード上 Resist は加速度項にしか効かず、定常速度では同定できない。
対策
システム同定モード (16 / 17) を配線。Ke / Km をデータシート逆算値 (0.00144 / 0.00130) にしたが実機で悪化し、経験値へリバート (現在は Ke 0.000975 / Km 0.0018)。
結果
データシート値では飽和 40.7 % / 速度誤差 stdev 138.6 に悪化、リバート後 n = 4 で飽和 31.9 % (基準 32.4 %) に復帰。
教訓
データシート値はギア損失などを含まない。理論値への置換は実機検証してから確定する。
2026-08-22

IMU 加速度計の有効化 (Stage 1)

同定保留
症状
t2200 ターンで内部推定より約 15 mm 手前で停止 (スリップ疑い)。エンコーダだけではスリップを検知できない。
原因
ASM330LHH の加速度計が未使用 (Z 軸ジャイロのみ) で、独立した運動情報がなかった。
対策
ジャイロの DMA 読みを 9 バイトに拡張して X/Y/Z を取得、gyro_pos のレバーアーム補正、静止ゲート付きの重力校正 (gain 0.92〜0.95) を実装。
結果
走行中の補正後加速度は真値 2250 mm/s² に対し平均 16.6 mm/s² で S/N 不足。自己位置推定への統合は保留、粗い異常検知用途のみ有望。
2026-08-22〜23

壁 PD の I 項再設計と Kanayama の並列化

制御完了
症状
高速直進の壁 PD に I 項がなく最大 6.5 mm の残留バイアスが加速度抑制 LUT と噛み合って加速度を 50〜90 % カット。安易に I 項を足すと壁ロスト ⇄ 過修正で発散 (角度 ±65°)。
原因
「逆符号のときだけ減衰」型のアンチワインドアップは同方向に持続する壁誤差に不適。既存の str_ang_pid.i は探索モードの D 係数として流用されていた。
対策
高速専用 str_ang_pid_fast (条件付き積分 + 絶対クランプ) を新設。kanayama_straight (ky / ki → 角速度目標のオフセット) を並列に追加。計画側の ego_in.w に直接足していた自己汚染は sen_kanayama_dw 経由に修正。
結果
p 0.0375 / i 0.00375 / d 0.0325 で発散なし。Kanayama 単独は収束 240 ms で直接注入 (40 ms) より遅く、並列構成で ey stdev 0.6 mm・±1.5 mm に収束。
教訓
既存のアンチワインドアップのパターンを別ループへ転用しない。新規フィールドはファーム更新に加えて yaml の再送が要る。
2026-08-22〜23

dump1 中の再送とアラーム再アームの喪失

ソフト完了
症状
センサーダンプ (mode 14) の実行中に Param Console から sensor.yaml を送ると SensingTask の 1 kHz 処理が恒久停止 (Planning は動き続ける)。
原因
IRQ での timer_hw->alarm[N] 生書き込みに、フラッシュ書き込みによる Core1 停止が重なると目標時刻が過去になり、32 bit が一周する約 71 分まで一致しない。ダンプ中の USB ポーリング追加で機会が増えた。
対策
arm_alarm32_safe() で書き込み直後に時刻を再確認し、追い越していれば INTF で強制発火。ハンドラ先頭で INTF をクリア。sensing の alarm 1 と planning の alarm 0 に適用。
結果
実機で再現・特定して修正。ダンプ中に yaml を再送して校正値をその場で確認できるようになった。
2026-08-23

Kanayama 2D の修正と終端ブレーキの復元

制御完了
症状
2D Kanayama を全モーションに拡張すると壁誤差 0.35 → 2.71 mm、|kim_theta| 0.34 → 5.42° と悪化。SLA_BACK_STR 後に w_lp が −20〜−35°/s 振れる。
原因
e_theta の基準が退化した ang_kf、dx の片側クランプ、ログの上書き。角速度の振れは同日朝のコミットが有効だった turn_end_brake を「未使用」と誤って削除したため。
対策
e_theta を kim.theta + last_tgt_angle 基準へ、dx クランプ削除、2D Kanayama を SLALOM / SLA_BACK_STR 限定に戻す。turn_end_brake を復元し p 0.0008 / d 0.0015 / slew 0.006 を追加。
結果
SLALOM n = 8 中 7 本が逆オーバーシュート 1° 未満。
教訓
enable = 0 の構造体やフラグは実機チューニング中の一時無効化かもしれない。削除前に git blame で経緯を確認する。
2026-08-23

旋回後のヨー保持 turn_angle_fb

制御適用済み・要検証
症状
45° ターン終端で kim_theta が目標に届かず、直進中も無補正でドリフト。角度 PID は基準 ang_kf が計画値そのもので実質無効。
原因
直接 duty 注入は角速度 PID の積分が外乱とみなして相殺する。SLALOM 中に sen_kanayama_dw が更新されず直前の壁追従値 (0.3〜0.4) が凍結して旋回を跨いでいた。
対策
turn_angle_fb (gain / gain_i / gain_d = SLALOM 限定の duty 注入、i_w_gate の連続重み、w_gain = 角速度目標オフセット) を実装。制御なし区間で sen_kanayama_dw = 0、壁の新規検出時に ang を 0 へスナップ。
結果
kim_theta が 400 tick 後に 0.045° へ収束することを単発ログで確認。n ≥ 4 の反復は未実施。
2026-08-23

吸引時の摩擦 FF と減速 LUT

制御保留
症状
吸引 ON の加速で左 duty が 99.9 % に張り付き v_c が目標の 2 倍近く跳ねる。約 6 m/s からの急減速で片輪スリップのヨーキック −2〜3°。
原因
摩擦 FF は吸引 OFF で調整した値で荷重 +250 g を未反映。decel 入力は減速開始タイミングの判定にしか使われず、減速度は毎 tick 距離から逆算される。
対策
coulomb / viscous_friction_suction を新設し吸引指令 > 1100 µs で切替。速度別の減速度上限 LUT (decel_v_max) を追加したが効果なし。
結果
吸引側の摩擦 FF は 09-05 / 09-07 に同定。減速レートの出力側クランプ案は未着手。
教訓
配列パラメータはキー欠落時に前回値が残る。配列の空 / 非空ではなく明示フラグで ON / OFF する。
2026-08-23〜09-05

Param Console のダンプ破損

ツール完了
症状
バイナリログ受信で稀にクラッシュ、または raw_byte 列だけの壊れた CSV (690,626 行)。再書き込み直後はヘッダー 144 行が丸ごと消える。
原因
pico-sdk の USB stdout がホスト無応答 500 ms で残りを静かに破棄しヘッダー行が欠落 (本体は毎回 576 で割り切れ健全)。再書き込み後は再接続前に送信が始まっていた。
対策
先頭の ready___:<byteSize> との突き合わせと型検証、USB stdout タイムアウトを 3 秒へ、書き込み後は接続確認まで待機。破損時は部分復元せず dumpFailed トーストで再試行を促す。
結果
サイレント破損が毎回検出されるようになり無意味な CSV は出なくなった。
2026-08-29

kim 座標系のリベース漏れ

ソフト完了
症状
左 → 右の連続スラロームの 2 本目で、odm_y は 0 なのに kim_y が kim_x と 1:1 で 30.8 mm まで成長し、角度 PID が荒れる。
原因
kim.x/y はワールド角度基準の増分をそのまま加算し、セグメント境界でリベースされる kim.theta / odm と座標系がずれていく。
対策
増分を pos_theta_z − kim.theta で逆回転してから加算。同日 Lm を 3.5e-7 へ下げた (4.3 倍過大と判断) が、これは 09-05 に誤りと判明。
結果
修正後 kim_y は 0.00〜0.08 mm (修正前 30 mm 超)。右ターンのみ角速度 I 項が −9〜−20 と負バイアスする左右差は n = 4 で残存。
2026-08-30

左前タイヤの接地不良

ハード完了
症状
右ターンだけ角速度 I 項が −13.9 と負バイアス。片輪ずつのシステム同定で duty 5 % は左が 86 % 速く、duty 15 % は右が 24 % 速い非単調な左右差。右駆動時は従動側が −96〜−114 mm/s で引きずられる。
原因
機械点検で四輪中の左前タイヤが浮いていた。荷重とグリップの配分が左右非対称だった。
対策
車高調整で四輪接地に修正。片輪選択のシステム同定モードと duty 列ログの修正を追加。
結果
駆動輪速度差 24 % → 0.2 %、超信地の左右差 4 %、右ターンの I 項 −13.9 → −1.89。同定と通常巡航 duty が 3〜6 % 差で一致し Ke / Km / Resist の再調整は不要と判断。
教訓
非単調な左右差は、制御側の非対称補正より先に機械側を疑う。
2026-08-30

壁積分の dt スケーリング

制御完了
症状
低速直進で壁誤差は ±2.5 mm なのに積分が 120 ms でクランプ ±90 に到達し −10〜−90 で暴れ、姿勢が微振動。
原因
sen.error_i += error_p が dt なしで毎 tick 積算。ただし dt を掛けてゲインを比例再スケールしても数式上は何も変わらず、効くのは ki とクランプの比率変更のみ。
対策
dt スケーリングは単位統一として残し、kanayama_straight.ki を dt 後の単位で 6.0 → 4.0 へ実質削減、windup_i_max = 0.09。
結果
積分が 0〜−0.09 で増減、壁誤差の P 項最大 2 mm 未満、kim_theta 最大 1.3° (n = 3)。
教訓
「dt を掛ける」だけの修正は比例再スケールなら何も変えない。まず数式的に no-op かを確認する。
2026-08-30〜09-05

SLALOM 入口の超過と Lm の 17 倍過小

同定完了
症状
v = 1800〜2100 の SLALOM 入口で w_lp が計画を最大 58 % 超過、片輪 duty が −50 % 台で内輪速度が負に。角速度 PID の積分ゲインを 1/3 にしても +48 % のまま。
原因
横系 FF ゲイン Lm = 3.5e-7 が約 17 倍過小で、alpha = 5180 で FF が duty 3 % (必要 ≈ 70 %) しか出ず PID が肩代わり。08-29 の「Lm 過大」は飽和領域での誤判断。副産物で SLA_BACK_STR の座標系リセット漏れも発見。
対策
差動トルク指令と実ヨー角加速度の最小二乗で 6.67e-6 / 5.73e-6 と 2 本一致し、Lm 6e-6 へ。cp_request のリセットに SLA_BACK_STR を追加、kim.x/y を last_tgt_angle ぶん回転。
結果
ヨー FF ピーク 3.0 % → 52 %、終端角度誤差 +12.8° → +7.4°、内輪速度の最小 −316 → +96 mm/s。BACK_STR 中の二次オーバーシュートが消失。
教訓
飽和下では FF を増やすと早く飽和して悪化に見える。Lm を触る前に軌道 (pow_n / rad / v) を実現可能にする。

9 月前半

2026-09-05

ターン FF 予算の監査と front の左右統一

制御完了
症状
dia45 で「右だけ大回り」。全 136 ターン定義中 47 件が FF 差動 duty > 75 %、pow_n = 6 の dia45 は全件 200 % 超で物理的に出せない指令だった。
原因
旋回終端姿勢が左右で約 2° 違い斜め直進で横ずれに育つため、位置補正の front / back では収束しない。front / back の左右差は非対称バグの打ち消し跡。
対策
設計式 FF% = 0.0130 × alpha_peak、a_lat = v² / rad / 9810 で監査 (FF ≤ 58 %、a_lat ≤ 9.0 G)。t_1800 dia45 は pow_n 4 → 2 / rad 52 → 44、t_2300 large は rad 60 → 67 など。t_1800 の front / back を左右統一。
結果
統一後は角速度超過率が左右一致 (112.3 / 112.0 %)、残る終端角度差は片側 0.75°。90° で pow_n を下げると rad 縮小 → 12.2 G で破綻 (実証)。
教訓
footprint は pow_n と rad だけで決まり v に依らない。pow_n の変更は横 G の余裕を見てターンごとに判断する。
2026-09-05

直進 FF の同定と 110 Hz リミットサイクル

同定完了
症状
高加速直進で速度 PID の I 項が毎 tick 平均 −2.0 V (duty −18 %) を打ち消し、積分が −2700 まで巻く。400 mm/s 巡航で duty の 71.7 % が 60〜200 Hz (110 Hz) に集中。
原因
Mass 0.040 / viscous 0.001475 が全速度域で約 30 % 過大。摩擦 FF の sign 対策が巡航中に旧値を永久ラッチ。速度 PID の d が p の 2.1 倍で高周波ゲイン過大。
対策
ff_check.py で (accl, ideal_v) 回帰し Mass 0.0302、viscous(_suction) 0.00036 へ。ラッチ条件に入力非ゼロを追加。d 半減 (8.75e-6)、i 3.75e-6。
結果
I 項 −2.0 → −0.48 V、距離誤差 2.5 → 1.5 mm、ピーク速度 4.91 → 5.42 m/s。60〜200 Hz RMS 1.254 → 0.367 で 110 Hz トーン消滅。
教訓
開ループ同定ログ (PID が動いていない) は FF 比較に使えない。並進 duty のスペクトルは (duty_l + duty_r) / 2 で見る。
2026-09-05〜06

壁積分の正帰還と壁切れ判定

制御適用済み・要検証
症状
壁の切れ目で壁 PD の出力が ±5° のレールに張り付き w_lp ±150°/s の bang-bang 振動。低速の SLA_FRONT_STR で壁 PID が 1 tick ゼロ落ちし角速度目標が約 +1 rad/s 跳ぶ。
原因
壁誤差の積分が姿勢 θ と同相 (S = 1.9〜3.0) で ki × S > angle_pid.p の発散側。切れ目判定は tick ごとの生差分で実効感度が速度に反比例し、正規化後は低速でしきい値がノイズ (p95 0.19〜0.25 mm/tick) 以下。
対策
kanayama_straight.ki 4.0 → 1.0 (安定条件 ki < angle_pid.p / S)。差分を速度で正規化 (kireme_diff_v_ref 2200) しノイズ下限 0.3 mm/tick と併用。壁ロスト中は積分停止。
結果
切れ目区間で 46 % の tick が壁棄却 (従来 0 %)、ゼロ落ち 189 / 488 → 23 / 488。ki = 1.0 は壁センタリング力不足とのトレードオフ。
2026-09-06〜09-22

hold 中の回転と吸引ランプの反動

制御完了
症状
吸引ランプ中 (1600〜1900 µs) に w_lp が 50 Hz 級で ±2〜7°/s 揺れて角度がランダムウォーク、プラトー後はスカート摩擦で固着し差動 duty 8 % でも動かず 0.2〜0.8° 残留。
原因
旧 hold の角度 I ゲイン 0.04 では 0.5° の残差に duty 3.7 % / 2.5 s しか育たず実質無効。DShot 化後の実測はランプ最速帯で −0.29°、終了時 +0.23° 戻り (片側 5 % ≈ 7 mN·m)。
対策
hold の I を角度基準の reset-on-move 化 (0.15°、gain 2.0、LPF 50 ms)、|kim| < 0.15° が 300 ms 続くまで待つ hold_settle を導入、DShot 後はプラトー基準で min 100 / max 500 ms。ランプ形状・糸吊り試験・差動 FF は提案のみ。
結果
unhold 時の残留のバッチ平均 0.50° → 0.06°。
2026-09-06〜09

start_align とクラブ角の正体

制御完了
症状
